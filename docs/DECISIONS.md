## 当前工程选择，不等同于最终玩法定案

- core/scenes 分离，规则方法修改状态，表现层负责输入与绘制。
- 当前 16×12 地图、32 像素格子、三列水面、100 木材、建造消耗 10，都是学习占位值。
- 双视图原型已完成，后续拟用阮小二与农田演示实时生产；这不意味着已经定下阮小二的正式职业或农田适配规则。
- 用单一固定敌军比较箭楼布局，是建议的防守验证方法。
- 实时生产已实现（P04）：暂停/继续按钮、逐田进度；倍速、后台与离线行为按 D14 不做补算。
- 中文 UI 使用嵌入的 Noto Sans SC（OFL 许可，随仓库分发），不再依赖系统字体回退；2026-10-04 因浏览器无法显示中文而提前落实（原 P21 项）。
- 3D 选中高亮为贴地黄色边框，与地块重叠显示；用户 2026-10-04 明确否定悬浮式高亮。

## 已被替换或不可直接沿用的旧方案

- “每旬结算”“一年 36 旬”“下一旬按钮”已被实时经营替换。招募、威胁和其他曾按旬触发的规则也要重新设计，不能直接移植。
- 原先把 2D 直接替换为唯一 3D 视图的建议，已改为共用状态的双视图；TileMapLayer 不是必须引入的技术。
- VPS 和三机同步不是当前前置任务。
- 20 好汉、10 建筑、32×32 地图、三种资源、四种职业是旧 AI 的示例规模，未锁定。
- “每回合按统率发令牌”是旧 AI 提案。用户原意是限制指令变更次数；按整场还是按回合分配预算尚未决定。
- 先装 GUT、强制所有类配测试、预建完整事件总线或 JSON 配表体系，不是当前工程要求。
- 固定高度层数、伤害公式、威胁阈值、15 分钟战斗等均不是用户确认的数值。

## 待定：实现对应功能时再讨论

| 问题 | 影响 |
| --- | --- |
| 正式 2D 战略界面的打磨范围、3D 相机旋转/缩放、正式模型与精灵的组合方式 | 立体感、遮挡、点击交互与素材成本 |
| 实时经营的产出周期、暂停/倍速、后台运行行为 | 时间推进和玩家观察节奏 |
| 战斗时城镇生产暂停还是继续，战后是否另行计算经过时间 | 两种时间系统如何衔接 |
| 指令预算按整场还是每回合分配；旧指令如何持续 | 战斗策略与交互 |
| 回合上限、掠夺胜利条件、占领过程、撤退规则 | 攻防体验 |
| 道路优先还是道路限定，建筑是否阻挡通行，水路/坡道规则 | 地图与寻路 |
| 正式资源种类、职业限制、招募/来袭触发机制 | 经营循环 |
| 损伤、修复、俘获、占领与掠夺的具体反馈 | 战后状态持久化 |

不要为了后续问题阻塞当前独立的小任务，也不要默默把候选方案升级成用户决定。
