# 经营系统 spec（E00）

更新日期：2026-10-12。本文以 `GameplayDesign.md` 最后一段总结和用户本轮确认结果为准；附件前文的建议只有在这里明确写入后才算项目约束。

## 设计目标

玩家从有限的城镇基础开始，通过人口、岗位、生产、施工和好汉逐步扩大一座可见的城镇。实时经营不使用“旬”；玩家需要始终能理解当前的短期处理事项、中期建设目标和长期成长方向，但不通过逐栋收税、逐人点击或物流微操制造忙碌。

战斗属于后续系统。经营阶段先完成资源、人口、施工、民生和军需的可玩基础；军需可以先作为经营压力和耗粮来源出现。

## 已确认的第一版方向

- `TownState` 是唯一模拟真相；2D、3D 和 UI 不各自推进规则。
- 新建和生产建筑升级都进入施工流程，有工期；建筑工决定并行施工能力，未能立即施工的项目进入队列。
- 生产建筑最多三级，每级提供离散的产能、岗位、外观或功能变化。民居按条件自动升级，生产建筑由玩家主动升级。
- 人口按岗位类别自动填充。玩家设置类别优先级与人数上限，建筑按填充率获得产出；阮小二和当前 P07 的单人岗位只是兼容教学原型。
- 地图数据按 60×60 起步验证，但坐标、占地、存档和渲染不得依赖固定 16×12；未来可扩展到 180×180 或更大。
- 河上使用桥；湖泊/水泊使用两个或以上码头形成水路。第一版不支持挖河或填湖。
- 好汉采用“定时抽样、带盘缠停留消费、盘缠耗尽离开、招募后可坐镇”的方向，不设置硬人数上限。抽样间隔、概率和消费数值待后续确定。
- 军需资源与兵力、持续耗粮先作为经营系统；战斗规则另行定稿。
- 第一阶段保留暂停，不加入倍速。
- 第一阶段不实现税率和民富，避免在人口/施工基础未稳定前扩大经济模型。
- 招募的目标规则是“由已入伙好汉说服”；具体消耗、时间和失败条件待定。

## 规则层边界

`core` 负责地图、人口、岗位、资源、建筑运行实例、施工队列、升级和存档数据。`scenes` 负责输入、绘制和反馈。任何按钮都通过规则方法请求状态变化，不能直接改资源或通过动画回调决定结算。

所有模拟入口接收游戏时间而不是帧数或墙钟。长时间步必须与拆成多个小步得到相同结果；施工完成、资源结算和队列出队必须幂等。存档显式编码坐标、占地、等级、队列和人口/岗位数据，不保存 Node 引用。

## 暂不锁定、实现前必须再确认

好汉抽样间隔/概率/候选权重、盘缠和消费速率；说服消耗与失败条件；粮食耗尽的软失败；仓储容量；繁荣度公式和台阶；岗位最终列表与建筑归属；各资源和工期的正式数值；战斗时经营时钟如何处理。

## 首个编码切片的验收边界

E01–E04 之前不得引入税率、民富、好汉抽样或战斗。首个可运行切片应能在 60×60 地图上放置多格建筑，看到人口与闲人、自动填岗、施工队列和三级升级的最小路径；旧 P07 场景仍能启动，存档版本迁移失败时不得破坏当前状态。
