# 练习：同一座城镇，两种视图

这次只需完成“建造 → 切换 → 比较 → 重置”，不必先理解三维数学。

## 1. 打开与运行

打开已有 Suiko 项目；无需新建。如果游戏正在运行，按 F8 停止，再等待编辑器重新载入文件。
若提示磁盘文件已变化，选择从磁盘重新加载。你若另外做了未保存修改，先保存副本，避免把新文件覆盖成旧版。
在左下“文件系统”双击 scenes/main/main.tscn，按 F5 或右上角运行按钮。

默认应该看到斜俯视的立体地图，右侧有“切换到 2D”和“重置城镇”。初始没有农田，木材为 100。

注意区分两组按钮：Godot 编辑器顶部的“2D / 3D”只切换编辑工作区；游戏运行后右侧的“切换到 2D / 3D”才切换城镇画面。
当前地形在运行时生成，编辑工作区里看不到完整地图，不能用编辑器顶部标签代替游戏内切换。
三维农田中的小屋只是占位外观，和二维黄色农田表示同一个建筑。

## 2. 验证共享状态

1. 点击绿色地块：出现农田，木材变为 90。
2. 点击“切换到 2D”：查看黄色农田，木材仍为 90。
3. 在 2D 的另一个绿色格子建造：木材变为 80。
4. 切回 3D：应看到两座农田，木材还是 80。
5. 点击已有农田或蓝色水面：应给出原因，不扣木材。
6. 点击“重置城镇”：恢复空地图和 100 木材；切到另一视图也应为空。

两个视图方向不同，3D 中左侧水带斜着显示，2D 中竖直显示。用水边和相邻地块的位置辨认同一座建筑。
关闭游戏再运行会重置，没有存档。

## 3. 认识节点

按 F8 停止，再看主场景的节点树：

- Main 是控制器，负责同一份城镇数据。
- MapArea 是接收地图点击的矩形区域。
- Map2D 把格子画成色块。
- WorldViewport 像一台拍摄三维小世界的相机屏幕，WorldImage 把它显示到界面中。
- Town3D 是一个复用的子场景，里面有 Camera3D、灯光和模型容器。
- UI 是共用界面，所以两种视图看到的是同一组资源数字和按钮。

建筑和地块在运行时由脚本生成。编辑器中看不到完整彩色地图是正常的。
想看实际生成的对象：F5 运行后，在场景面板切到“远程/Remote”，展开 WorldViewport → Town3D → Terrain 或 Farms。
远程检查用于观察运行状态；本次练习先不修改远程属性，运行时改动通常不会保存到场景文件。

## 4. 第一处代码阅读

打开 scenes/main/main.gd，找到 town 的创建，以及 _ready() 中的两行：

```gdscript
map_2d.setup(town)
map_3d.setup(town)
```

它们传入的是同一个对象。这就是为什么切换画面时建筑不会丢失，也是后续只需写一份经营规则的基础。

完成这次操作后，下一课做“选中农田并显示信息”，之后再安排阮小二工作与实时产粮。

## 遇到 Node2D / Node 类型报错

若出现 `Script inherits from native type 'Node2D' ... object of type 'Node'`，先核对本项目主场景和脚本是否混用了旧版。
当前 main.tscn 的 Main 是 Node，main.gd 首行应为 `extends Node`，其地图路径应为 `$MapArea/Map2D` 和 `$MapArea/WorldViewport/Town3D`。
早期单视图代码使用 `extends Node2D` 和 `$MapView`，不能重新贴回当前主场景；只改 extends 也无法补齐缺少的切换逻辑。
收到外部文件修改提示时，从磁盘重新加载修复后的脚本，然后 F5。若未保存内容需要保留，先另存副本，避免覆盖新文件。
